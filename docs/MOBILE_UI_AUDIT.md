# 手机端 UI 走查记录

> 2026-11-01 · 版本 1.161.2 · 走查人：DeepSeek Harness（deepseek-v4.1-flash）
>
> 这份文档是手机 UI 大改造的输入：记录在真实浏览器里从头到尾用一遍手机界面时遇到的每一处不合理，附实测数据与涉及组件。改造时按节引用，不需要再复现问题。

## 0. 走查方法

| 项 | 内容 |
| --- | --- |
| 视口 | 390 × 844（DPR 2，主流手机）；553 × 845（实测用户设备近似值）；830 / 1400 用于断点对照 |
| 载体 | 本地 `dist` 构建 + `wrangler pages dev`，真实 `local-data` 数据（只读操作，未改动任何资料） |

## 1. P0 · 阻断级（影响主流程）

### 1.1 顶栏溢出：主操作被推到屏幕外，且没有任何提示

**实测（390 宽，风格串页）**

| 控件 | 左边缘 | 是否在视口内 |
| --- | --- | --- |
| 展开文件夹 | 12 | ✅ |
| 搜索框 | 61 | ✅ |
| 筛选与排序 | 189 | ✅ |
| 批量选择 | 241 | ✅ |
| 查找相似 | 291 | ✅ |
| 风格串分享包 | 340 | ✅（贴边） |
| **收集模式** | **385** | ❌ 完全不可见 |
| **批量导入** | **433** | ❌ 完全不可见 |
| **新建风格串** | **481** | ❌ 完全不可见 |

内容总宽 513px，可用 366px，溢出 147px。

**影响**

- 「新建风格串」是这一页最主要的创建入口，在手机上默认不存在，用户必须知道「顶栏可以横向滑动」才可能找到；而横滑提示只有右缘 28px 的渐隐，视觉上更像装饰。
- 同类的还有角色库（「+ 新建」被切一半）、Pixiv（「关注」被切）、提示词库（分区按钮被切）。
- 溢出量随按钮数量线性增长，这不是个别页面写错，而是**把桌面「一排工具 + 横滚」范式直接搬到手机**。

**涉及**

`components/DesignSystem.tsx` 的 `WorkspaceToolbar`、`index.css` 的 `.workspace-toolbar-scroll`，以及各页面自绘的顶栏内容（`ChainList`、`CharacterLibrary`、`ArtistLibrary`、`PixivGallery`、`PromptLibrary` 等 15 处 `WorkspaceChrome` 使用方）。

### 1.2 实验室：底部生成条与底部导航重叠

**实测（390 宽，实验室页）**

- `.mobile-generation-actions`：`top: 747`、高 45 → 底边 792
- `.app-mobile-nav`：`top: 777`
- 重叠 **15px**
- 同页还有一个 `fixed inset-x-0 bottom-*` 的 44px 高悬浮按钮（`top: 801`），**完全落在底部导航的 777–845 区间内**，被导航整块压住
- 生成条下方的「Anlas —/— · 生成额度 —」一行同样被切

**影响**：生成条是实验室唯一的提交入口，它的下沿与「风格串／资源库／实验室／历史／设置」死贴在一条线上，视觉上像两套导航打架，且被压住的按钮点不到。

### 1.3 创作助手：输入框被底部导航覆盖

**实测（390 宽，助手面板展开）**

- 输入面板：`top ≈ 724`，底边 `≈ 816`
- 底部导航：`top 777`
- 覆盖 **39px**，正好压住输入框底部一行和工具行（图片、完全访问、模型名、语言、下拉）

**影响**：输入框最下方的工具行有一半在导航下面，点不到；面板高度没有扣掉底部导航 + 安全区。

### 1.4 三种弹层形态混用，同一类操作没有固定手势

**实测**

| 入口 | 形态 | 关闭方式 |
| --- | --- | --- |
| 风格串「筛选与排序」 | 底部 sheet（`MobileBottomSheet`） | 拖拽把手 / X |
| 资源库菜单 | 底部 sheet | X（无把手可拖） |
| 全局设置 | 全屏 modal（12px 四周留白 + 圆角） | X |
| 设置二级「外观与画廊」 | 全屏 modal + 返回箭头 | ← 回到分类 / X 关全部 |
| 历史灯箱 | 全屏层 | ← |

**影响**

- 用户无法形成「从下往上滑出 = 临时选择」「全屏推进 = 进入下一层」的心智模型；同样是"关掉一层"，有时靠下滑、有时靠 X、有时靠 ←。
- 设置里 ← 和 X 并排出现，但两者一是"上一层"、一是"全关"，图标大小和位置都没有区分。

## 2. P1 · 明显影响效率与观感

### 2.1 卡片上的悬浮圆钮密度过高

**实测**

| 页面 | 单卡圆钮数 | 说明 |
| --- | --- | --- |
| 角色库 | **最多 7 个** | 左上「排除」、右上「收藏」、左右「上一张/下一张」、右下「编辑／下载／复制」 |
| AITag | 2 个 | 左上「层叠 ×」、右上「收藏」 |
| 收藏库 | 1–3 个 | 右上「收藏」+ 长按后的删除/下载/复制 |
| 画师库 | 2–4 个 | 左上「排除」、右上「收藏」，部分卡还有「模板／版本」 |
| 历史 | 1 个 | 右上「收藏」 |

**影响**

- 390 宽下每张卡只有 175px 宽，44px 圆钮一放就是封面面积的 1/4；角色库那张卡被 7 个圆钮围成一圈，缩略图基本看不清。
- 圆钮只有图标没有文字，「层叠 ×」「⊘」这类图标语义要靠猜。
- 这些按钮在触屏上靠长按显现（`press-reveal`），但按钮本身常驻 DOM 且占据命中区，容易与滚动、点开冲突。

**建议方向**：触屏统一改成「长按 → 底部 action sheet」，一行一个 44px 高的带文字项；卡面只保留 0–1 个主操作。

### 2.2 收藏库：每张卡都顶着亮粉色实心爱心

收藏库内所有条目必然是「已收藏」，但每张卡右上角仍显示亮粉色实心爱心，一屏 10 张就是 10 个高饱和圆点，在暗色背景上跳动感极强，且**零信息量**。

### 2.3 触控目标小于 44px 的清单

| 页面 | 控件 | 实测尺寸 |
| --- | --- | --- |
| 创作足迹 | 刷新统计 / 导出 CSV / 打开历史 | 37 × 44 |
| 创作足迹 | 顶栏标题「创作足迹」被压成「创…」 | 37 × 44 |
| 历史 | 创作足迹入口 | 37 × 44 |
| Roll 串 | 管理记录 | 28 × 44 |
| 设置 | 导出主题按钮 | 22 × 44 |
| 设置 | 强调色圆点 | 32 × 32 |
| 实验室 | 退出实验室 / 使用提示词 / 收录提示词 | 40 × 44 |

全局 CSS 有 `button { min-height: 44px }`，但只约束高度、不约束宽度，于是出现大量 22–37px 宽的细条按钮。

### 2.4 资源库菜单 9 项排成 2 列，末行是孤儿

资源库 sheet：Roll 串、画师库、角色库、提示词库、AITag、法典、Danbooru、Pixiv、收藏库 —— 9 项 2 列 = 4 行 + 第 5 行只有「收藏库」占左列，右侧空一格。同一菜单里「收藏库」又恰好是使用频率最高的一项，却被排在最孤独的位置。

（3 列 × 3 行可以正好铺满；或按「创作 / 素材 / 外部源」分三组，每组内部成对。）

### 2.5 文本截断与信息层级

- 提示词库片段卡：正文摘要与标题视觉层级接近（摘要居中灰色多行、标题加粗在下方），单卡内出现 10 处文本截断（如「男孩牵链前行·女孩身后跟随」149px 容器 / 174px 内容）。
- Pixiv 卡：标题被安全模式打成灰条后，与作者名、点赞数三层文字难分主次。
- 历史灯箱顶栏：第一行时间戳 + 第二行「V5 Full · 768 × 1344 · heart P1」11px 小字 + 右侧「1 / 12245」+ ⓘ，四组信息挤在 44px 高的顶栏里。

### 2.6 空状态没有行动引导

- Roll 串空状态：一个收件箱图标 + 「暂无匹配候选」，下方 300px 纯空，没有「去挑几个风格串」的入口。
- 顶栏同时显示「画风记录 17」「提取画师 已选 3 串 · 27 位画师」「Roll」三个大块，其中前两个在空状态下并不能推进流程。

### 2.7 「费用未知」

实验室生成条：「生成 1 张 · 费用未知」。Anlas 余额未就绪时直接显示"费用未知"，且底部状态行同步显示「Anlas —/— · 生成额度 —」，两处负状态叠加。

### 2.8 设置页滑块与主题预览

- 「移动端列数 / 桌面端列数」滑块轨道仅 2px 高、拇指直径约 14px，远低于 44px 触控区。
- 主题卡里嵌了一张桌面截图缩略图，在 390 宽下整张预览仅 460 × 240，细节不可辨，却占了近 500px 高度。
- 设置分类一级页 6 张大卡占满首屏后，下方留 300px 空白。

### 2.9 创作足迹热力图

- 顶栏标题被压成「创…」
- 热力图只露出 1–5 月共 5 列，6–12 月需要横向滑动；底部一行与屏幕底边齐平
- 大数字卡片占掉整屏（作品总数 12,177 / 活跃天数 135 / 连续创作 13 天 / 历史收藏 17 / 最常用风格串 / 最常用画师），热力图被挤到首屏之外

### 2.10 灯箱

- 左侧「删除」与右侧「收藏」对称放在图片左上/右上，危险操作与安全操作同等显眼、同样大小
- 两侧翻页按钮对比度过低，在亮色画面上几乎不可见
- 底部缩放条 `− 51% + 适应窗口 100%` 与图片底边贴合，图片下沿被工具条盖住

## 3. P2 · 打磨项

1. **顶栏与分区条双层导航**：实验室顶部同时有「← / 文生图 / 图生图 / 局部重绘 / 扩图 / ⋯」和「全局 / 角色 / 场景 / 参考 / 参数」两层横排 tab，第二层里「全局」是一个蓝色大块、其余是纯文字，同层级却是两套视觉。
2. **实验室首屏大片空白**：「画风」文本框之间、下方空白约 150px，且没有画布/预览。
3. **重复信息**：Pixiv 页「已加载 70 件」（状态行）与子导航「70 件作品 · 可加载更多」表达同一件事。
4. **状态行字号**：「共 1891 条」「已加载 100 位」「片段 · 匹配 22 条 · 共 22 条」为 12px 居中细字，紧贴顶栏下沿，与卡片区没有分隔。
5. **橙色警告横幅**：「助手服务 1.161.1 尚未加载最新代码。请关闭原服务窗口，再启动工坊；只刷新页面不会更新后端。」——这是开发期提示，直接暴露给使用者。
6. **AITag 卡左上「层叠 + ×」**：图标组合无法从视觉判断是"已缓存"还是"移除缓存"。
7. **孤立绿点**：AITag 顶栏最左侧有一个无标签绿点，与搜索框同行，用户无法知道它代表什么。
8. **设置页嵌套层级**：卡片套卡片再套分段控件，暗色下三层灰阶几乎不可分。
9. **滚动条压在卡片上**：列表右侧 6px 滚动条与卡片边缘重叠。

## 4. 系统性根因（改造时要一起解决的）

1. **桌面优先的顶栏范式**：`WorkspaceToolbar` 的默认行为是「一排控件 + 放不下就横滚」。手机上可用宽度 366px，而多数页面顶栏需要 500–900px。横滚在触屏是隐形的，等价于把功能藏起来。
2. **没有统一的移动端顶栏契约**：15 个页面各自往 `WorkspaceChrome` 里塞控件，没有「标题 / 返回 / 主操作 / 更多」的槽位定义，所以每个页面溢出位置都不一样。
3. **hover 语义直接搬到触屏**：卡片操作依赖 `hover-reveal` / `press-reveal`，触屏上要么看不见、要么常驻占位。
4. **弹层没有统一契约**：sheet / modal / popover 三种形态按页面随意选，关闭手势不统一。
5. **断点只有一个 768**：手机、平板、窄窗全塞进同一套手机规则；768–1023 区间既没有侧栏优势也没有手机手感。
6. **触控尺寸只约束了高度**：`min-height: 44px` 管不到宽度，于是出现 22px 宽的按钮。
7. **安全区与浮层叠高未统一管理**：底部导航 68px、生成条、助手输入框各自 `fixed`，没有统一的 `--mobile-bottom-inset`。

## 5. 改造建议（供决策）

### 5.1 导航骨架

- 底部 5 个 tab 保留，但把「资源库」的 9 项格子改成**分组列表 sheet**（创作 / 素材 / 外部来源 三组，每组 2 列成对，无孤儿）。
- 引入 `--mobile-bottom-inset = 底部导航高度 + safe-area`，所有 `fixed` 浮层（生成条、助手输入框、FAB）统一用它做支撑，禁止各自写 `bottom-[...]`。

### 5.2 顶栏范式（建议统一为三槽）

```
[返回/标题 ............ 主操作] [⋯ 更多]
```

- 左槽：返回或页面标题（可截断，最小 88px）
- 右槽：**恰好一个**主操作（风格串＝新建、提示词库＝新建片段、图库＝筛选）
- 其余全部进「⋯」底部 sheet，每行 44px + 文字标签
- 保留搜索：搜索框独占第二行或折叠为图标展开，不再与工具抢同一行

这样 390 宽下任何页面都不需要横滚。

### 5.3 卡片

- 卡面常驻 0–1 个主操作（收藏）；其余（下载、复制、删除、编辑、发到实验室）全部进长按 action sheet。
- 收藏库内不显示"已收藏"心形（状态恒为真，属噪声）。
- 需要方向键翻页的卡片（角色库）改成左右滑动手势 + 角标「2/6」，不再画两个 44px 圆钮。

### 5.4 弹层契约

| 类型 | 形态 | 关闭 |
| --- | --- | --- |
| 临时选择（筛选、更多、资源库） | 底部 sheet，把手可拖 | 下滑 / 点遮罩 |
| 进入下一层（设置二级、详情） | 全屏推进 | ← 返回 |
| 需要专注的任务（灯箱、编辑器） | 全屏 | 顶部单一 ← |

### 5.5 触控与排版

- 所有可点元素 ≥ 44×44（宽度也约束）；细条按钮改为「44px 方形图标 + 文字」，文字进更多菜单。
- 状态行、卡片元信息统一到 13px 起，11px 只用于极次要信息。
- 危险操作（删除）不与安全操作对称摆放；进 action sheet 并标红。

### 5.6 列表底部

统一 `padding-bottom: calc(var(--mobile-bottom-inset) + 12px)`，替换现有 0/12/16/80/112/160 六种取值。

## 6. 改造验收清单

- [ ] 390 宽下所有页面顶栏**无横滚**，无按钮被切
- [ ] 任何可点元素 ≥ 44×44
- [ ] 底部导航、生成条、助手输入框、FAB 相互不重叠，且都让出 safe-area
- [ ] 弹层形态只有三种，关闭手势一致
- [ ] 卡片常驻按钮 ≤ 1，其余走长按 sheet
- [ ] 空状态都有「下一步」入口
- [ ] 列表底部留白统一，最后一项完整可见
- [ ] 亮/暗、玻璃/实色四种外观下均逐条复查
